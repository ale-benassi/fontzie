# Fontzie design

Fontzie is a compact typography inspector alongside the active website. The website supplies the live specimen; the editor uses a restrained monochrome interface with red reserved for destructive actions.

## Identity and type

Use the supplied vector wordmark and its quiff-shaped f. The sidebar and floating editor share `components/BrandLogo.vue`; production vectors live in `public/branding/`. The toolbar icon renders the complete `fontzie-mark.svg` in charcoal on a transparent background. `npm run icons:generate` preserves its viewBox and transforms when creating the packaged icon sizes, using an SVG renderer without launching a browser.

Use locally bundled Inter for interface text and JetBrains Mono for selectors and technical values. The base interface size is 14px. Font-family specimens render in the family being considered.

The sidebar, floating editor, dialogs and notifications share the Inter root family and Tailwind sans token. Bundle the weight-variable font through `@fontsource-variable/inter`; retain existing sizes and weights. UI font copyright notices and SIL Open Font License 1.1 texts are included in `public/licenses/THIRD-PARTY.txt`. Interface fonts load locally without Google Fonts requests.

`npm run fonts:generate` writes both UI fonts' original WOFF2 files and `ui-fonts.css` into `public/fonts`, retaining every weight and Unicode range. The application links the packaged stylesheet through `chrome.runtime.getURL`, keeping font requests on the extension origin during development and production. Regenerate these assets when updating either font package.

## Composition

- A compact sidebar header contains the wordmark, floating-editor action, theme control and Preview switch. Its background matches the main Surface, without a separate gray band. Exact picks and editable CSS selectors occupy one target field; shortcuts append targets. Keep Headings, Paragraphs, Links and Whole page visible below the field as compact text actions with a quiet “Add:” label, without individual outlines or a shaded strip; let the row wrap only when needed in narrow panels. Separate the shortcuts from the target input with a thin line inset 8px from both sides.
- Rule rows use the crisp monochrome treatment: white surfaces in Light, fine borders, 8px between rows and transparent drag handles. Drag handles stay transparent on hover and sit inside the row’s 2px editing outline, with matching inner corner radii. Keep row focus rings visible and menus outside the scrolling surface.

Reserve the overflow ellipsis for additional targets. Recalculate the visible chips when the available width or targets change. During rule selection show the checked-rule count. The whole bar, including its summary and chevron, opens one keyboard-accessible dropdown aligned to the content width, with the shared 4px trigger offset. The dropdown contains only a compact rule list, with wrapping target chips, font names and a selected state. Do not repeat current targets or add section headings. Share the target-chip presentation with the main Rules panel; keep rule management actions in that panel. Keep a 4px gap between rule switcher rows. Switching selects one rule, exits bulk selection and preserves the editor's scroll position. The bar and target chips do not navigate back to Rules. Keep the bar mounted with persistent visible and hidden transform states so interrupted motion reverses from its current position. Allow 8px of scroll travel back across the Rules boundary before hiding to avoid jitter. It is inert while hidden or leaving; Reduce Motion removes these transitions. The bar overlays the scrolling surface without shifting it; scroll-to-section actions leave headings clear of it. Restore the active rule and its targets together when reopening or reconnecting; keep blank rules selected and discard unrelated prior picks. Keep the switcher available during any temporary state with saved rules but no selected rule, showing “Choose rule”. Hide it without a connection or saved rules, and disable it while picking or busy.
- The Rules header's actions menu contains Select rules… and Select all rules. Each rule row becomes a keyboard-accessible checkbox, with read-only visibility indicators in place of visibility buttons. Done or Escape exits selection and returns focus to the header menu. Select all and the editing count sit above the scrolling list. Clear selection and Delete sit below it. Checked rules use the shared Font family and Typography controls. - The first successful target entry creates and selects a saved rule, even before typography changes. Further targets and typography edits update that rule; New deliberately starts a separate blank rule. Empty Rules previews a single blank rule using the real row styling, with its drag handle, visibility and menu icons, Original font and zero changes. The header picker also stays available when Targets is collapsed. Choose the target document automatically through the element picker; do not expose a manual page/frame chooser. Reveal the first rule and its selected targets so the relationship between Targets and Rules stays visible; additional rule creation also reveals Rules.
